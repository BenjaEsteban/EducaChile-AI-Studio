# Azure Blob Storage Setup

EducaChile AI Studio can use MinIO for local development and Azure Blob Storage for production. The application stores only object keys and metadata in PostgreSQL; uploaded files, avatar images, audio, slide renders, and generated videos live in object storage.

## Production Setup

1. Create an Azure Storage Account.
2. Create a private blob container, for example `educachile-assets`.
3. Copy the storage account connection string from Access keys.
4. Configure the API and worker with:

```env
STORAGE_BACKEND=azure
AZURE_STORAGE_CONNECTION_STRING=DefaultEndpointsProtocol=https;AccountName=YOUR_ACCOUNT;AccountKey=YOUR_KEY;EndpointSuffix=core.windows.net
AZURE_STORAGE_CONTAINER=educachile-assets
AZURE_STORAGE_PUBLIC_BASE_URL=https://YOUR_ACCOUNT.blob.core.windows.net
WAVESPEED_API_KEY=...
WAVESPEED_BASE_URL=https://api.wavespeed.ai/api/v3
```

5. Deploy the same values to both `api` and `worker`.

Do not commit real Azure connection strings or account keys. The frontend receives only temporary SAS URLs generated by the backend.

## Local Development

Keep using MinIO:

```env
STORAGE_BACKEND=minio
MINIO_INTERNAL_ENDPOINT=http://minio:9000
MINIO_PUBLIC_ENDPOINT=http://localhost:9000
```

WaveSpeed talking-photo generation no longer requires a public asset URL for the avatar image when the project avatar is uploaded and stored in Azure. The worker downloads the avatar image from storage, uploads it to WaveSpeed, and passes the temporary WaveSpeed upload URL to the talking-photo endpoint.

## Talking Photo Settings

The default avatar mode uses Wavespeed AI Talking Photos:

```env
WAVESPEED_API_KEY=...
WAVESPEED_BASE_URL=https://api.wavespeed.ai/api/v3
```

ElevenLabs remains optional for future advanced voice modes.
